# 1. システムで確認する観点

| 観点       | 確認内容                      | よくある問題               |
| ---------- | ----------------------------- | -------------------------- |
| 文字コード | UTF-8 / Shift_JIS / CP932など | 文字化け                   |
| DB         | VARCHAR/NVARCHAR、照合順序    | 保存できない文字           |
| API        | HTTP Content-Type / JSON      | `charset`不一致            |
| ファイル   | CSV、TSV、固定長              | Excelだけ文字化け          |
| 文字数     | 文字数とバイト数              | VARCHARサイズ超過          |
| Unicode    | サロゲートペア                | emojiで長さ判定がおかしい  |
| 正規化     | NFC/NFD                       | 見た目同じなのに一致しない |
| 全角半角   | `Ａ` と `A`                   | 検索でヒットしない         |
| 改行       | LF / CRLF                     | CSV・Linux/Windows間の問題 |
| 制御文字   | TAB、改行など                 | CSVやログが崩れる          |
| HTML       | `<>&"'`                       | XSS・表示崩れ              |
| SQL        | `'` など                      | SQL構文への影響            |
| URL        | 日本語・記号                  | URLエンコード問題          |

# 4. Unicodeで重要なテスト
## ⑦ Emoji
😀
👍
❤️
🎉
🚀

これは特に Javaで文字数判定するときに注意します。
例えばUTF-16を内部表現として扱う環境(javaなど)では、
😀
が単純な1コード単位として扱えない場面があります。
そのため
```
java
str.length()
```
だけを「人間が見る文字数」と考えると問題になるケースがあります。


## ⑧ 結合文字

かなり重要
例えば、

```
が
```

にはUnicode上、

```
が
```
という1文字として表す方法と、

```
か + ゙
```

のように、

```
U+304B  か
U+3099  濁点
```

を組み合わせる方法があります。

見た目は同じでも、内部データが違うことがあります。
この問題が、Unicode正規化（NFC / NFD）です。
Macで作ったファイル名とWindows/Linux間などでも遭遇することがあります。


# 5. Emojiよりさらに厄介な文字

例えば、以下の家族の絵文字

```
👪
```

人間には1文字に見えますが、内部的には複数のUnicodeコードポイントを
ZWJ（Zero Width Joiner）で連結しています。


したがって、「最大20文字」という仕様なら、何を1文字と数えるのかを決めないといけません。

# 10. システム設計として特に決めるべきこと

    UTF-8 / Unicode

    UTF-8

    UTF-8

    Unicode対応

    UTF-8 BOM付き

## 特に覚えておくとよいポイント

文字コード関連のテストは、大きく分けるとこの5分類で考えると整理しやすいです。

① 普通の文字
→ ASCII、日本語

② 日本特有の文字
→ 半角カナ、髙、﨑、𠮷、①、㈱

③ Unicode特殊文字
→ Emoji、結合文字、ZWJ

④ システム上特殊な文字
→ ' " \ < > & % ,

⑤ レイアウト系
→ 半角/全角スペース、TAB、LF、CRLF
